Strategic Roadmap

Goals, Scope & Key Architectural Decisions

Defining explicit boundaries, technical trade-offs, and criteria for determining whether distributed CPU inference can ever be practical.

1. In-Scope vs Out-of-Scope

In Scope (What We Build)
  • Single open-weight LLM split across multiple CPU nodes.
  • Automated profile parser and model placement planner.
  • Systematic latency, bandwidth, and node-count sweeps.
  • Reproducible benchmark output in JSONL / CSV formats.
Out of Scope (Non-Goals)
  • No production web service, SLA, or multi-tenant API.
  • No GPU or CUDA kernel optimization work.
  • No LLM training or fine-tuning pipelines.
  • No Kubernetes, Nomad, or Ray cluster orchestration.

2. Why This is Worth Doing

Even if distributed CPU inference yields modest speeds (e.g. 1-2 tokens/sec), uncovering the exact quantitative tipping points between memory bandwidth saturation and network serialization latency provides invaluable foundational insights into distributed systems engineering.
