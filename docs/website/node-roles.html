What Runs on the Master vs. Workers

Clarification of the single codebase principle: you do not write separate software for master and workers. Machine bootstrap is identical across all nodes.

Identical Machine Setup: Every machine (master or worker) runs the exact same bootstrap script (Ubuntu 22.04 / 24.04, dependencies, compiler, pinned engine binaries). The only thing that differs is which executable and flags systemd or the runner launches!

Can the Master Also Act as a Worker?

Yes! In fact, in a small 2-node cluster (such as two 1 OCPU Oracle Arm VMs), the master node computes the early transformer layers (e.g. layers 0–13), and the remote worker computes the remaining layers (e.g. layers 14–27).

If the cluster has plenty of worker RAM, the master can also be configured with coordinator_computes=false, dedicating 100% of its CPU to tokenizer, KV-cache orchestration, sampling, and HTTP streaming.
