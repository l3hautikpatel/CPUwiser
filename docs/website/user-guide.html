Operator Guide

User Guide, CLI Commands & Node Monitoring

Complete operational reference for managing cluster profiles, inspecting node health, launching inference sessions, and running benchmarks from your laptop.

1. Standard Team Vocabulary

Term Definition & Role
Master (Referred to as coordinator in code). The single machine you talk to; hosts the API, tokenizer, and sampling logic.
Worker A cluster machine holding allocated model layers; communicates exclusively with the master over RPC.
Node Any host in the cluster (master or worker).
Profile A declarative YAML file defining the hardware topology (nodes, CPU cores, RAM, network latencies).
Plan The deterministic recommendation generated by the planner (layer splits, thread allocations, quantizations).
Overlay Private WireGuard VPN subnet linking machines across local Docker, Oracle, or AWS.

2. Complete CLI Command Reference

The cpuwiser CLI executes locally on your developer laptop and communicates with nodes via SSH or Docker:

Profile & Planning Commands

# List available cluster profiles
cpuwiser profile list

# Show detailed specifications of a profile
cpuwiser profile show oracle-2xa1

# Set the active profile
cpuwiser profile select oracle-2xa1

# Preview planner recommendations for a model on the active cluster
cpuwiser plan --model qwen3-0.6b --engine llama-cpp

Node Health & Status Commands

# Display cluster status table and health of all nodes
cpuwiser status

# Deep diagnostic health check on a specific node (SSH, RAM, binary versions)
cpuwiser check arm-node-02

# Live streaming resource stats (CPU usage, memory, network I/O)
cpuwiser top

Runtime & Chat Session Commands

# Start the cluster (boots engine binaries on workers, then master)
cpuwiser up

# Open terminal chat session directly to the master node
cpuwiser chat

# Gracefully terminate the active session and stop engine processes
cpuwiser down

4. Node & Cluster State Lifecycle

Node States
  • UNREACHABLE: Ping/SSH fails.
  • IDLE: Machine is reachable; engine process not running.
  • STARTING: Engine starting; loading weights.
  • RUNNING: Engine listening; answering RPC heartbeats.
  • ERROR: Process crashed or out-of-memory.
Cluster States
  • DOWN: All node processes stopped.
  • DEGRADED: Some workers missing; cannot infer.
  • READY: Master + all planned workers healthy.
  • SERVING: Actively streaming token inferences.

5. Day-to-Day Operational Walkthroughs

Scenario A: Starting Your Daily Session

  1. Run cpuwiser profile select oracle-2xa1 to choose your cluster.
  2. Run cpuwiser up --model qwen3-0.6b. The CLI establishes SSH connections, launches ggml-rpc-server on workers, and then starts llama-server on the master.
  3. Run cpuwiser status to confirm all nodes report RUNNING.
  4. Open your browser at http://localhost:3000 or run cpuwiser chat to interact with the LLM!

Scenario B: What to Do If a Node Dies Mid-Run

  1. Run cpuwiser status to identify which worker dropped offline.
  2. Run cpuwiser check <node-name> to test whether the SSH connection is alive or if the OOM-killer terminated the process.
  3. Run cpuwiser down followed by cpuwiser up to restart clean, or switch to the laptop simulation profile with cpuwiser profile select docker-sim.
