Runbook & Operations

Docker Simulation & Cloud Infrastructure

Operational runbooks for local Docker container simulation, userspace delay proxies, and Oracle Cloud Always Free compute topology.

1. Simulation Environments Overview

Primary Testbed

Laptop Docker Lab

All worker nodes execute as isolated Linux containers connected via private Docker bridge networks. Enables rapid iteration without cloud provisioning costs or latency jitter.

Real Hardware

Oracle Always Free VMs

Genuine distributed environment across Ampere A1 (Arm) and AMD E2.1 Micro shapes connected via private VCN and optional WireGuard mesh overlay.

2. Network Emulation with tc netem

To reproduce physical WAN conditions inside local Docker, container interfaces are throttled using Linux kernel traffic control queuing disciplines: 

# Inject 5ms one-way delay (10ms RTT) with 0.5ms jitter on worker interface
tc qdisc add dev eth0 root netem delay 5ms 0.5ms distribution normal

# Throttle bandwidth to 100 Mbps
tc qdisc change dev eth0 root netem delay 5ms rate 100mbit

# Clear emulation rules
tc qdisc del dev eth0 root

3. Strict Security Rules

RPC Insecurity Warning: The llama.cpp RPC server does not authenticate callers and trusts all memory offsets. Never bind a worker port to 0.0.0.0 on any public interface. Bind solely to 127.0.0.1 or internal VCN IP addresses protected by security lists.
