Documentation Audit & Conflict Resolution

Comprehensive review of pack inconsistencies, superseded instructions, and authoritative rulings to eliminate ambiguity for human and agent developers.

Authoritative Priority Rule: When two documents disagree, the newer companion document takes precedence over older files. CLI-START-HERE.md and DOC-AUDIT.md represent the ultimate rulings.

Identified Conflicts & Final Rulings

Area of Ambiguity Older Document Stance Authoritative Final Ruling
Default Model Earlier files suggested SmolLM2-360M or Qwen2.5-0.5B. Qwen3 0.6B (quick baseline) and Qwen3 1.7B (main runs). Only Qwen3 is supported by both llama.cpp and distributed-llama for A9 engine comparison.
License Selection Earlier files left the license open (MIT, Apache, or AGPL). MIT License. Permissive, simple for portfolio projects, and aligns with upstream engines.
Oracle Multi-Account Policy Early exploratory drafts discussed multiple free accounts. Strictly 1 Account. Creating multiple accounts violates Oracle ToS and risks termination. Use 1 account (2x A1 1 OCPU/6GB) + optional AWS guest node or laptop.
Terminology: Master vs Coordinator Older files used "coordinator" everywhere. Master is used in user-facing documentation, CLI output, and UI. In internal Python code, the field name remains coordinator. CLI accepts both.
Local Simulation Priority Unclear whether cloud or laptop came first. Laptop Docker first (M0 to M3). Build and prove all test suites locally before touching cloud VMs. Oracle setup runs in parallel.

Pre-Development Checklist for Developers

  1. Read CLI-START-HERE.md and GUARDRAILS.md before writing application code.
  2. Ensure Python 3.12 and uv package manager are installed locally.
  3. Verify Docker Desktop / Colima is running for the local simulation environment.
  4. Never commit any IP addresses, SSH keys, or .env files to git.
