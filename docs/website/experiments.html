Experimental Protocol

Experiment Matrix & Latency Sweeps

Every hypothesis is tested with 5 measured runs per configuration, median + p95 latency tracking, warm-up runs, and strict control baselines.

Tier A: Laptop Simulation (Docker + tc netem)

ID Experiment Name Variable Swept Core Hypothesis to Confirm/Disprove
A1 Single-Node Baseline Thread count (1 to host logical cores) Finds the peak single-machine tok/s beyond which memory contention slows generation.
A2 RPC Loopback Overhead Coordinator + 1 RPC worker on loopback Measures raw serialization and context serialization tax with 0ms network latency.
A3 Latency Sweep (Core) Injected RTT: 0.1ms, 0.5ms, 1ms, 2ms, 5ms, 10ms, 20ms Charts token-per-second collapse slope against round-trip delays.
A4 Hop Count (Node Count) 2, 3, 4 worker nodes with fixed total model Quantifies whether adding nodes improves throughput or degrades into network communication overhead.
A5 Bandwidth Sweep 10 Gbps down to 10 Mbps throttled link Determines minimum network throughput needed for weight synchronization vs prompt streaming.
A6 Prompt Length & TTFT Input prompt tokens: 32, 128, 512, 1024, 2048 Computes prompt processing (prefill) latency distribution across workers.
A7 Failure Injection Worker killed mid-stream via SIGKILL Validates adapter crash-detection, error bubbling, and cluster heartbeat reporting.
A8 Heterogeneity Tuning Unequal split ratios (e.g. 70% to node 1, 30% to node 2) Ensures fast cores do not idle waiting for slow cores during all-reduce steps.
Reproducibility Mandate: No performance figure may appear in results or documentation without an exact commit hash, raw terminal log reference, and hardware specification string.
